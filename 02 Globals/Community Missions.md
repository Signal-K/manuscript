Proposed strategy for these community missions -

We’ll create a new community hub-type structure which can be accessed by anyone on that planet. The hub allows for data or anomalies to be transported to these other planets (e.g. from #Earth) and be investigated in the unique location (including the different physics (sim) etc). Users who establish the hub will be able to request different anomalies and set the standard for what is being investigated at different times. Users can shuttle anomalies from Earth or other locations for a bounty, paid out “by the bank” and 5% goes to the creator of the hub. Research points & consensus can also be attributed here. Similarly users can establish community factories and other structures. Anomalies from off-world will go to those structures and “live there” before they are investigated by users (their investigated instance goes to the user’s structure, and points to the base instance which stays in the hub).

Community missions for astronomers can be centered around establishing communication beacons which add more content like SETI data and long-form relays (removing some arbitrary limit, maybe? Or open up the less verifiable/reliable data?).

And obviously communication stations need to be established for users to be able to send their classifications/contributions and communiques back, ideally we should create some sort of map so we can determine how often these stations need to be made.

Simple ideas for community missions would essentially be setting up the community structures so that users can unlock relationships and allow for data from other anomalies to help populate other anomalies (e.g. once we start getting some data from Mars' terrain, we can build a station on Mars & Mercury to then “develop” the terrain on Mercury and bring that classification method to Mercury).

As well as the basic community factories. Eventually users will need to establish community stations for all anomalies when they’re not on #Earth which then pass the data into the new locations (imagine they function as “interpreters” for data that maps it to #Earth/Solar-system -like params). They can serve as the method/area to add new data sources to, by voting on them. Locations will also need a way to transmit data back (classifications won’t be eligible to participate in consensus until they came from a location with a transmitter).

Question - how do community missions allow for better data classification without just limiting available data (because all data should be accessible from essentially the start of the game?). Community missions need to therefore make things more accessible, as a convention of the mission, not just be a purely arbitrary in-game asset.

Possibly we add soundscapes as an upload mechanism to populate the [game] world(s) and then also provide something else to classify?
Maybe we have community consensus on generator/physics scripts that take user classifications and then build up a map of how that data format could be transferred to other settings/anomaly types. Users need to vote on anomaly types. This is where #Starnet comes in.

Possibly community missions involve setting policies and guidelines for uploading and classifying data, and then linking to the above script ^.
